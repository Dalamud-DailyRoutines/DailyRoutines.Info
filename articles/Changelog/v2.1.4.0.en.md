## Framework Modifications

- Anomalies while loading Daily Routines in certain environments have been fixed.
- An issue existed in the route `Goblet → Ul'dah - Steps of Thal` has been fixed.
- Now it will automatically focus on the map flag while accessing the in-game map via Daily Routines.
- The efficiency of reloading Daily Routines has been greatly improved.
    - Now the resource management while loading and unloading Daily Routines is dynamic and self-adaptive based on the real-time situation.
    - The instantiation time of many modules has been improved.
    - Connection requests have been removed from the initiation.
    - Batch loading and unloading now take place on Framework to prevent the resource waste caused by thread switching.
- New `Compact View` has been introduced for the module list. After enabling the view, all the module cards would be presented in a single line including the title, the description and the checkbox only. A view toggle has also been introduced in the top-right corner of the module list.

![CompactView](/assets/Changelog/2.1.4.0/CompactView.webp)

- An issue of unexpected acquisition attempts regarding TID in Wine environment has been fixed.
- MID in Wine environment now takes machine GUID in registry since it's more stable.
- The appearance of all the toggles has been improved for better perception.

## New Modules

### Auto Highlight Sprint [Action]

*Recommended Module*

Automatically highlight the action "{0}" if it's not in combat in duty.

### Auto Umbral Soul [Action]

Automatically execute the action "Umbral Soul" after joining a duty, experiencing a wipe or leaving combat if the current job is "Black Mage".

### Auto Reveal Treasure Location [System]

*Recommended Module*

Automatically reveal the treasure location after deciphering or checking a timeworn map.

### Custom Map Mark [Interface]

*Recommended Module*

Provide custom map marks for the in-game map, supporting comments, groups and batch import & export.

### Better Auto Follow [System]

- The logic has been fully refactored.
- Now the following status, like `following`, `paused` and `waiting for target`, is now explicit. Now the following will resume if the target re-appear.
- Now the following process will resume after some user operations, like manually moving, executing an action, casting, switching zones and watching a cutscene.
- A short delay has been introduced before resuming the following after manual movement.
- A flexible donut has been introduced while following, to prevent unexpected rapid operations while the distance is just around the following threshold.
- The vnavmesh following has been improved. Now it supports wayfinding at point-blank range, better path update and returning to the vanilla in-game following if exceptions occur.
- Now the right-click menu will indicate the following status in real time.
- New command `/pdrfollow stop` to manually stop following.
- The logic of mounting, flying and dismounting according to the target's status has been improved.
- An issue that the update period was not accurate enough has been fixed. An issue that the module may try to follow an unavailable target constantly in some rare cases has been fixed.
